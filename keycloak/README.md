# Keycloak realm configuration

`lyra-realm.json` in this directory is the production-shape realm: the realm roles (`parent`, `teacher`, `admin`)
and client scopes (`parents.read`, `kids.create`, ...) the application's `@RequiredAccess` model depends on. It
deliberately carries no client and no users:

- **Clients** are an environment-specific, operational decision (confidential vs. public, which grant types, real
  redirect URIs, a client secret) that belongs to whoever provisions each real Keycloak instance - not something to
  invent or commit here. Provision one per environment via your normal Keycloak admin process, and never commit its
  secret.
- **Users** are real people in production; there is nothing to define here at all.

Test-only fixtures - the test client (`members-api-test`, public and password-grant-enabled purely for automated
testing convenience) and the fixed set of test users a real deployment would never have - live in
`src/test/resources/keycloak-fixtures/test-fixtures.json`, deliberately outside `src/test/resources/keycloak`:
`KeycloakTestContainer` mounts that whole directory as Keycloak's `--import-realm` source, which imports every
`.json` file in it as a full realm, so a fixtures fragment sitting alongside the generated realm would break the
import. The full realm Testcontainers imports for tests (`src/test/resources/keycloak/lyra-realm.json`) is
generated by merging this file's roles and client scopes with those test-only fixtures - the security vocabulary
is defined once, here, so tests and production can never drift apart on what a role or scope means. After changing
roles or client scopes, regenerate it and commit the result:

```shell
./scripts/generate-test-keycloak-realm.sh
```
